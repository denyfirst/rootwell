    What these labels mean

    The CA flag and possible issuer links are public-certificate evidence, not proof that a root is trusted. This view does not select a leaf, verify a complete chain or hostname, check revocation, or contact a server.

    Tool 03 / Verify

    Verify a TLS server certificate

    Planned flow: add one certificate or several files from your CA. Rootwell will explain what it found before asking you to make a trust decision.

    Explicit trust
    1. 01
      Add what your CA gave you

      One .crt or .cer, a PEM bundle, or several public certificate files. No need to know which is the leaf yet.

    2. 02
      Enter the website name

      For a TLS server check, tell Rootwell the hostname the certificate should protect.

    3. 03
      Choose what you trust

      Use a separately selected company root or, later, a reviewed public-root profile. A root found inside the uploaded bundle is never trusted automatically.

    Advanced: what will be checked?

    The same verification engine will use an explicit leaf certificate, optional intermediates, an independently chosen trust anchor, hostname, evaluation time, and policy. Automatic file classification will not change the trust decision.

    What this profile will not claim

    No OCSP, CRL, Certificate Transparency, private-key possession, or live endpoint check. A local file verdict is not deployment evidence.
