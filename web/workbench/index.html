            Tool 04 / Request certificate
            Create a certificate request
            
              
            A CSR is a signed request you send to your certificate authority (CA). It is not a certificate. Your private key stays here; never send it to the CA.
            
            Local processing
          
            
          
            
            
            1. Choose your key and site names
            
            
            
            
            
              
              
              
            
                
            
                
            
              
            
              
            Use a fresh random 20–128 character non-space ASCII password and save it in your password manager. Rootwell does not keep it. The download is a ZIP containing the encrypted key and public CSR; the ZIP itself is not encrypted.
            
            
            
            
            
              
              
              
            Leave it blank for an unencrypted key. PKCS#8, RSA PKCS#1 and EC SEC1 are supported; encrypted keys must use the supported modern PKCS#8 profile. PFX and legacy encrypted PEM are not accepted here. Only the CSR is downloaded; your existing key is not copied.
            
              
            Opening a password-protected key does not prove its origin or integrity. Use a trusted copy of your key.
            
              
            
            
            
            
            One DNS name per line, or separate names with commas. Maximum 32. No https://, port or path. Wildcards use *.example.com; international names need punycode. The first name becomes the common name; TLS names come from this list (SAN).
            
            
            IP addresses and organisation details (optional)
              
              
            
                
            
                
            
                
            
                
            
                
            
              
            
              
            These are requested values, not identity proof. Your CA decides what to include. At least one site name or IP address is required.
            
            
            
            
            
            
          
            
          
            Already have a CSR? Open it here
            
            
            DNS/IP CSR profile only. Challenge passwords, unknown attributes/extensions and email/URI requests are refused, not silently ignored.
            
            
          
            
          
            
            
            2. Send only the CSR to your CA
            
            
              
            
              The request signature was checked locally. It does not prove identity, your possession of an imported request's private key, or issue a certificate. Keep the private key and its password safe; only the CSR goes to the CA.
              
            
            
            
              Technical request details
              
            
              3. Check the certificate your CA returns
              
            
            
              Choose the single site certificate, not a bundle. If your CA supplied a bundle, use Inspect to choose and download the site certificate first.
              
            
            
                
              
                Same key is not a trust check. A fake certificate can contain the same public key. Use Verify with the CA chain and an independently trusted root next; issuer signature, time, purpose, revocation and live deployment are not checked here.
                
          
                
        
                

        
                
          
                
            
                
              
                Tool 03 / Verify
                
              
                Verify a TLS server certificate
                
              
                Verify public certificate files locally against a separately selected trust anchor and hostname. No certificate upload, system roots, or live server check.
                
            
                
            Explicit trust
          
                
          
                
            
            
            
          
                
          
                Choose a root file separately. A root found in your CA's other files is never trusted automatically. For stronger identity assurance, compare its full fingerprint with one obtained from an independent trusted source and enter that value above. Copying the fingerprint from the same file proves nothing extra. Without a pin, Rootwell checks the chain against your selected root, not whether that root is authentic. Private keys and PFX are not accepted.
                
          
                Try it safely with public, non-production files: CA files and separate demo root; hostname verify.rootwell.invalid. For Advanced: leaf and intermediate. Never install the demo root in your OS or browser trust store.
                
          
                
            How would you like to add the public files?
            
            
          
                
          
                
            
            
                Rootwell requires exactly one end-entity certificate and treats CA certificates as intermediate candidates. Self-signed roots in these files are ignored, not trusted.

                  What this verdict does not prove
                  A matching pin confirms only agreement with the fingerprint you supplied; Rootwell cannot authenticate where you obtained it. Without a pin, root identity is unconfirmed. No OCSP, CRL, Certificate Transparency, private-key possession, or live endpoint check. A local-file verdict is not deployment evidence.
